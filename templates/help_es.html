Sky Observation Planner

Planifique sus noches de observación, explore la visibilidad de los objetos y convierta una lista de objetivos astronómicos en un programa práctico.

Sky Observation Planner facilita la planificación astronómica. Un gráfico interactivo de altitud nocturna muestra cuándo son visibles los objetos desde el observatorio seleccionado; otro gráfico muestra la visibilidad anual. Configure los límites de observación, examine la posición lunar y otras condiciones y encuentre periodos adecuados antes de utilizar el telescopio.

Puede comenzar con un catálogo CSV propio, el catálogo Messier incluido o una búsqueda de objetos en SIMBAD. Seleccione objetivos, organícelos en un plan y cree un horario de observación. La aplicación se ejecuta localmente y se abre en el navegador; los gráficos permiten ampliar, explorar datos al pasar el cursor y exportar imágenes.

Ejemplo del gráfico nocturno con la visibilidad de los objetos, la Luna y los intervalos de crepúsculo.

Primeros pasos

Sky Planner utiliza Python, Flask y Astropy. Conda resulta cómodo, pero no es obligatorio. Ejecute los comandos en la carpeta que contiene app.py y requirements.txt.

Instalar las dependencias de Python

Si usa Conda, active el entorno base para instalar los paquetes; ambos lanzadores de escritorio prefieren ese entorno cuando Conda está disponible:

conda activate base
pip install -r requirements.txt

Iniciar Sky Planner manualmente

python app.py

Abra http://127.0.0.1:5511 en el navegador. El puerto predeterminado es 5511; para cambiarlo, establezca SKY_PLANNER_PORT antes de iniciar la aplicación.

Instalar el lanzador GNOME (Ubuntu 24.04 y sistemas Linux similares)

Extraiga el archivo ZIP en una carpeta permanente. Abra una terminal dentro de esa carpeta y ejecute:

chmod +x launch_sky_planner.sh install_desktop_launcher.sh
./install_desktop_launcher.sh

Busque Sky Observation Planner en el menú de aplicaciones GNOME o en el escritorio (si están activados los iconos). El lanzador activa primero Conda base si está instalado; en caso contrario prueba .venv/venv del proyecto y luego Python 3.10+ con todas las dependencias. Inicia el servidor local y abre el navegador predeterminado. GNOME puede solicitar Permitir lanzamiento para el icono. Si cambia de lugar la carpeta de la aplicación, vuelva a ejecutar el instalador para actualizar las rutas.

Recargar la página conserva la sesión del servidor. Cerrar la pestaña o ventana vinculada normalmente detiene el servidor tras un periodo de gracia de dos segundos; si no llega el evento de cierre, se aplica el tiempo de espera de 90 segundos del heartbeat. Volver a abrir rápidamente el lanzador reconecta la sesión y cancela el cierre pendiente. La detección del cierre se realiza en la medida de lo posible. No se crea un acceso independiente para detener el servidor.

Sin Conda (Linux o macOS): en el directorio del proyecto extraído ejecute:

python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

Los lanzadores conservan la activación original de Conda. Solo si no encuentran Conda prueban .venv, venv, python3 o python (Python 3.10+ con todos los paquetes necesarios). Si encuentran Conda pero falla la activación de base, muestran un error en lugar de cambiar silenciosamente de intérprete. Los lanzadores no instalan dependencias automáticamente.

Instalar el lanzador Finder para macOS (Apple Silicon o Intel)

Instale las dependencias en Conda base (por ejemplo mediante Miniforge) o en un entorno virtual local según las instrucciones anteriores. Conda no es obligatorio. Conserve la carpeta extraída en una ubicación permanente y, desde Terminal dentro de ella, ejecute:

chmod +x launch_sky_planner_mac.sh install_mac_launcher.sh
./install_mac_launcher.sh

Se crea ~/Applications/Sky Observation Planner.app. Ábrala desde Finder (o mediante la búsqueda de aplicaciones de macOS). El lanzador prefiere Conda base, o utiliza .venv/venv o un Python del sistema compatible; inicia Waitress y abre el navegador predeterminado. No hace falta compilar con PyInstaller ni tener permisos de administrador. La .app apunta a la carpeta del proyecto; vuelva a instalar el lanzador si la mueve. Si macOS bloquea una aplicación descargada, utilice Abrir en el menú contextual de Finder o consulte Ajustes del Sistema → Privacidad y seguridad. Ejecute únicamente software de confianza.

Registro del servidor: ~/Library/Logs/SkyPlanner/server.log. Al iniciar desde Terminal pueden configurarse SKY_PLANNER_HOST (predeterminado 127.0.0.1) y SKY_PLANNER_PORT (predeterminado 5511). Recargar la página mantiene el servidor en funcionamiento y permite reconectar. Al cerrar la pestaña o ventana asociada, normalmente termina tras dos segundos de gracia; si se pierde la señal de cierre, actúa el timeout de heartbeat de 90 segundos. Volver a lanzar la aplicación rápidamente recupera la sesión y cancela el cierre pendiente. La detección de cierre del navegador es aproximada; una segunda pestaña sin el token de sesión no mantiene vivo el servidor vinculado.

2. Uso básico: proyectos y planes

Proyectos: catálogos reutilizables

Un proyecto es una colección de objetivos astronómicos con límites de observación predeterminados. Seleccione un proyecto existente o pulse + New para crear otro. Se pueden abrir varios proyectos a la vez. Añada objetos manualmente (+ target) o use Upload para importar un CSV. Con acceso a Internet, la búsqueda en SIMBAD puede completar las coordenadas a partir del nombre. La identificación SIMBAD es independiente de la fotometría Gaia G y la velocidad radial opcionales: su ausencia no impide obtener las coordenadas y la velocidad radial disponible se incorpora sin solicitarla expresamente.

Cada objeto tiene nombre, ascensión recta (RA) y declinación (Dec). La RA se expresa en horas y la Dec en grados; se aceptan entradas sexagesimales como 12:30:00 y +15:20:00. Las coordenadas originales se conservan aunque cambie su presentación.

El menú de proyecto ☰ permite modificar los valores predeterminados, exportar CSV y eliminar el proyecto. Puede arrastrar objetivos para reordenarlos o clasificarlos numéricamente por RA. La ordenación RA de un proyecto es independiente de la del plan. Use búsqueda, filtros, casillas de selección o selección múltiple para trabajar con varios objetivos.

Planes: elegir qué observar

Un plan contiene copias independientes de objetivos del proyecto. Cópielos mediante la flecha, selección múltiple o arrastrando y soltando. Un objetivo puede aparecer varias veces. Modificar o borrar una copia del plan no afecta al objetivo original del proyecto.

Cree planes con + New; en el menú ☰ puede cambiar la configuración, copiar el plan con otro nombre, exportar CSV o eliminarlo. Los objetivos se reordenan arrastrándolos y su orden importa en el modo Schedule. Sort RA ordena todos los objetivos, o solo los seleccionados cuando haya alguno, dejando los demás en su sitio. El orden queda guardado y puede modificarse después. Undo restaura hasta 30 modificaciones anteriores de la lista durante la sesión actual del servidor (ordenaciones, cambios de orden, adiciones y eliminaciones). La ordenación del proyecto es independiente.

Campos de los objetivos y límites de observación

El editor permite definir masa de aire máxima, iluminación lunar máxima (bright ≤100 %, gray ≤70 %, dark ≤40 %), distancia mínima a la Luna en grados, separación mínima de velocidad respecto a la luz lunar y de velocidad telúrica en km/s, así como la velocidad radial opcional del objetivo en km/s. Los límites de velocidad solo se aplican cuando se dispone de velocidad radial del objeto. Un límite de velocidad vacío lo desactiva.

También almacena tiempo de exposición (segundos), número de exposiciones (entero positivo), pausa (minutos en la interfaz; segundos en los datos guardados) y comentarios (hasta 1.000 palabras). El tiempo de exposición y la pausa aceptan valores decimales, como 2700.0; el número de exposiciones debe ser entero.

Los valores predeterminados del proyecto abarcan masa de aire, fase lunar, distancia a la Luna y límites opcionales de velocidades lunar y telúrica. Se usan para nuevos objetivos y pueden aplicarse a los objetivos existentes si se solicita.

3. Observatorios

Se pueden seleccionar los observatorios registrados en Astropy. Consulte la lista de ubicaciones en la documentación de Astropy. Empiece a escribir el nombre de un observatorio y seleccione una sugerencia de autocompletado. También se pueden añadir ubicaciones manualmente en sites.py.

4. Gráficos

Seleccione fecha y Location (observatorio) y después el modo de visualización. Pulse Update para calcular; mientras tanto, el botón muestra el estado animado Calculating. Plotly permite hacer zoom, desplazar el gráfico, interactuar con la leyenda y exportar imágenes. Los colores del gráfico son independientes del tema de la página, que sigue el aspecto claro/oscuro del sistema operativo. Arrastre el separador para cambiar el tamaño de los catálogos y del gráfico.

Altitud · una noche

El gráfico muestra la altitud nocturna de cada objeto, la altitud de la Luna, zonas de crepúsculo, hora UTC, tiempo sidéreo local y un eje de masa de aire. El título enumera los eventos solares calculados; pase el cursor sobre él para obtener explicaciones. La información emergente de los objetivos muestra altitud, masa de aire, separación lunar y velocidades pertinentes. Los intervalos de visibilidad baja aparecen atenuados o tachados; los símbolos de aviso marcan los objetivos o bloques que incumplen límites. Un objeto que permanece bajo el horizonte no es observable.

Horas visibles · año completo

Para cada noche del año seleccionado se estima cuántas horas cumple cada objeto los límites configurados. Use ☰ Settings para elegir el límite de altura solar: puesta de sol (0°), crepúsculo civil (−6°), crepúsculo náutico (−12°, predeterminado) o crepúsculo astronómico (−18°). Los límites de masa de aire, fase/distancia lunar y separaciones de velocidad también afectan al cálculo. Los incumplimientos aparecen en las curvas anuales. Los objetivos idénticos con coordenadas y restricciones iguales se calculan una sola vez y se indican mediante un contador.

La visibilidad se calcula mediante muestras temporales de aproximadamente dos minutos; las efemérides de velocidades se almacenan en caché y se interpolan para acelerar gráficos anuales posteriores. Estos resultados son estimaciones de planificación, especialmente cerca de los valores límite.

5. Programar observaciones

Abra el menú ☰ del plan y cambie Mode de Plan a Schedule. Aparecen opciones específicas:

  • Tiempo de exposición predeterminado, que puede aplicarse a todos los objetivos existentes del plan.
  • Pausa predeterminada entre exposiciones, también aplicable a los objetivos existentes.
  • Inicio de la observación: puesta de sol, crepúsculo civil, náutico (predeterminado) o astronómico.

El programa sigue el orden de los objetivos del plan. Cada objetivo constituye un bloque cuya duración es

(tiempo de exposición + pausa) × número de exposiciones.

El primer bloque comienza normalmente en el crepúsculo seleccionado para la fecha y observatorio; los bloques siguientes respetan el orden del plan. Desplace el control de tiempo para modificar el inicio. Con el control enfocado, pulse Espacio o seleccione Time… para usar la hora actual, introducir una hora UTC o volver al crepúsculo elegido.

Una banda translúcida identifica cada bloque programado; las curvas de altitud se dibujan encima. Los segmentos programados destacan y el resto se atenúa. Las líneas verticales marcan el comienzo y final. Pase el cursor por cualquier punto del bloque para consultar los datos del objetivo a la hora UTC señalada (altitud, masa de aire, distancia lunar y velocidades aplicables), parámetros de exposición y validez global del bloque. Las curvas de otros objetivos no reemplazan esta información emergente.

Cada bloque se comprueba durante toda su duración: si se incumple un límite en cualquier momento aparece una advertencia (también en la leyenda). Cambiar el orden, añadir objetivos o desplazar el inicio fuerza una nueva evaluación. El gráfico anual continúa mostrando horas observables no programadas.

Referencia de importación de catálogos CSV

Columnas obligatorias: name,ra,dec. Se admiten todos los campos canónicos siguientes. Los alias de la tercera columna no distinguen mayúsculas y minúsculas. Los límites opcionales no indicados adoptan los valores predeterminados del proyecto.

Campo CSV Descripción Alias admitidos
name Identificador del objetivo, obligatorio object, star, target, targets
ra Ascensión recta, horas (sexagesimal o decimal), obligatoria alpha, right_ascension, rightascension
dec Declinación, grados, obligatoria declination, delta
gmag Magnitud Gaia G (opcional) gaia_g, gaia_g_magnitude, gaia_gmag
moon Distancia mínima a la Luna, grados moon_limit, moonlim
airmass Masa de aire máxima airlim, airmass_limit
phase Categoría de iluminación lunar: dark / gray / bright moon_phase, moonphase
radial_velocity Velocidad radial sistémica del objetivo, km/s rv
moon_velocity_limit Separación mínima de velocidad respecto a luz lunar, km/s moon_rv_limit
telluric_velocity_limit Separación mínima respecto a velocidad telúrica, km/s telluric_rv_limit
exposure_time Duración de una exposición, segundos exptime
exposures Número de exposiciones, entero positivo nexp, number_of_exposures
delay Pausa por exposición, segundos delay_seconds
comments Notas de texto libre comment, notes
add Indicador de selección heredado, ignorado al importar proyectos plot, select, selected

También puede importar archivos CSV sin cabecera de tres columnas (name,ra,dec) o con los formatos heredados de seis o siete columnas descritos en la guía web. El archivo incluido tab_test.csv es un ejemplo deliberadamente irregular, con coordenadas sexagesimales mezcladas y sin encabezados.

Exportación CSV de horarios

En modo Schedule, Download exporta una fila por bloque de observación, en el orden del plan. Las primeras columnas contienen la identidad y las horas UTC de inicio, mitad y fin calculadas/programadas; se evalúan altitud, masa de aire y distancia angular a la Luna en esos tres momentos, además de velocidades baricéntricas, de luz lunar y relativas. Después aparecen tiempo de exposición, número de exposiciones y pausa. Solo después figuran las columnas default_* con los límites de observación y la velocidad radial configurados. Así se distinguen claramente los valores calculados de las restricciones configuradas. Sin velocidad radial estelar, los campos de velocidad relativa quedan vacíos. La exportación refleja observatorio, fecha y hora UTC inicial seleccionada mediante el control deslizante, cuando corresponda. Son valores instantáneos, no máximos ni mínimos de todo el bloque.

API de Python (arrays NumPy)

import obs
targets = obs.read_targets('tab_test.csv')
night = obs.staralt(targets, location='paranal', date='2027-12-31')
twilight = obs.twilights(location='paranal', date='2027-12-31')
year = obs.annual(targets, location='paranal', year=2027)

staralt() acepta rutas CSV, DataFrames de pandas y valores SkyCoord de Astropy escalares o vectoriales. Devuelve dos claves:

  • time: array NumPy datetime64[ns] con instantes UTC de la noche de observación.
  • targets: diccionario por nombre; cada objetivo contiene arrays NumPy float de altitude (grados), airmass, moon_distance (grados), barycentric_velocity (km/s), moon_velocity (km/s), moon_velocity_difference (km/s) y telluric_velocity_difference (km/s). Todos los arrays están alineados con time. Los nombres duplicados reciben sufijos #2, #3, etc. Si no hay velocidad radial, los dos arrays de velocidad relativa contienen NaN. La masa de aire bajo el horizonte es NaN. No se devuelven crepúsculos ni metadatos del gráfico.

twilights() devuelve únicamente un diccionario de eventos con claves sunset, nautical_dusk, astronomical_dusk, astronomical_dawn, nautical_dawn y sunrise; los valores son objetos datetime UTC de Python o None cuando el evento no ocurre.

annual() devuelve dates (NumPy datetime64[D], fechas de calendario locales del observatorio), time_utc (NumPy datetime64[ns] correspondientes a la medianoche solar media local muestreada según su longitud) y targets (nombre → arrays de métricas). Las métricas son observable_hours (integral de la noche completa), moon_distance, barycentric_velocity, moon_velocity, moon_velocity_difference y telluric_velocity_difference. Las distancias angulares se dan en grados y las velocidades en km/s. La medianoche solar media depende de la longitud y no de la zona horaria civil. Las horas anuales corresponden a la noche asociada a cada fecha, no a una medida instantánea.

Las salidas de la API están pensadas para análisis NumPy y no son serializables directamente a JSON. La aplicación web sigue usando sus interfaces JSON de gráficos independientes.
